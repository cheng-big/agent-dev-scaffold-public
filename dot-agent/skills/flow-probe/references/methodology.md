# 方法论展开（flow-probe）

本篇把 SKILL.md 的 8 步逐步讲透 + 判定口径表 + 两个端到端 worked example。参考实现是一个多系统业务平台的 `harness/`，用于展示完整闭环。

## 起点：流程规格长什么样
一个可测的平台通常有一份「业务流程规格」。以项目中的 `system.html` 为例，它的组织方式（多数流程文档同构）：
- 按**业务系统**分节（`<h3 id="sys-XXX">`，20 个系统）。
- 每系统下若干**编号流程**（`<h4 id="XXX-N">`，如 `test-1` = 流程1.1 体测预约）。⚠️**显示编号(3.1)与 DOM 锚点 id(venue-1)常是两套体系**，别猜，按实际锚点。
- 每条流程 = 一张 **时序图（sequenceDiagram）**，participant 分三类：①**角色**（实名用户/中心管理员/五大处室…）②**系统/端**（带圈码：⑪.1公众门户 / ⑪.2政务门户 / ⑫移动应用 / ⑬统一身份 / ⑭业务中心 / ⑰数据中台…）③**外部/硬件**（闸机/设备/卫健委…）。
- 每系统末尾一张**状态机表**（`state-flow`：当前态→目标态[触发条件]，按子对象分组）。
- 角色权限在 `rbac.html`：**只有中文名、无 code 列**——角色 code 要从时序图 participant + 代码侧「数据范围」语义映射。

> grounding 铁律：中立读「它到底定义了什么」，禁止预贴标签（教训：某"message"被预标"站内信"→建错系统，真源实为系统间消息队列）。

## 判定口径（写进每步 verdict）
| verdict | 含义 | 严重度 |
|---|---|---|
| PASS | 实测与应然一致，**且后端回查坐实** | — |
| MISMATCH | 能跑通但与应然口径分叉（状态合并/拆分/端不同），或断言不成立 | P2 |
| GAP | 应然有该步/该态，实现无对应落地路径 | P1 |
| ERROR | 非预期报错/5xx/异常 | P0 |
| INFO | 业务规则观察 / 跨系统 stub（实现未强约束，待业务确认） | 观察 |

每步还必带两维度：`sys`（端，按泳道，别全塞管理后台）+ `via`（UI=浏览器点真页面 / HTTP=直连接口）。

## 8 步展开
**① 抽泳道**：对目标系统的每条编号流程，从时序图逐步骤列「角色 + 端 + 是否跨系统」→ 步骤→端映射表。跨系统步骤（发短信/推送/数据同步/上链）标为对应支撑系统，多为诚实 stub。

**② 摸实现**：后端 grep controller 的 `@*Mapping` 找端点、entity/迁移找**状态字段枚举**、找种子账号；前端 grep 路由文件（`path:`/`component:`）、页面 `.vue` 的 `<el-table-column prop=>`（可见列，决定行怎么匹配）和 `<el-button @click=>`（动作按钮名）；公众端点 `/public/<域>/*`。

**③ 定账号**：管理操作员、各级审核员、公众/群众各一个浏览器上下文。**分级路由**是高频坑：审批实例区划常取**提交人**区划，提交人必须是辖区账号，否则对应审核员的待办为空（假绿/假红）。

**④ 写探针**（核心，见 assets/example-flow-probe.mjs）：
- 每条流程 `makeFlow(no, name, wbChain, note)`。
- 每步 `step(flow, name, expected, actual, verdict, via, detail, shot, sys, fix)`。
- **有页面的动作 → 浏览器点真按钮**：状态迁移用 `uiDrive(uiFn, verifyFn, target)`（点完后端回查是否到目标态，点不到 ok:false 判红）；行内操作用 `uiRowAction`；审核待办两节点用 `auditTodo(page, todoRoute, rowText, '通过')` 分别在 CITY/PROV 上下文点；新建对话框用 `uiBuild`；引用下拉用 `pickRemote`。
- **后端 `api()` 回查坐实**：建了 GET 单号、审了查状态迁移、对外展示断言 count≥1。
- **点不到就判红，不 HTTP 兜底驱动**；确实无页面的（后端不变式断言如 SLA/幂等、外部 stub、定时任务）诚实保留 `via:'HTTP'` 或 `verdict:'INFO'`。

**⑤ 起隔离栈跑**：`run-stack.sh <系统|all>` 建隔离库→迁移→后端→前端→Playwright→拆栈。**headless 先验**选择器/断言（快、无窗口）→ `HEADLESS=false` **有头出图**（截图为真、肉眼复核点页面）。

**⑥ 判定**：按上表；每步双维度 sys+via。

**⑦ 报告**：探针 `finalize()` 落 `systems/<code>.json`（机读，可直接编辑改流程/说明）→ `build-report.mjs` 合成 **`report.html`**（单文件交互：左选系统 / 右上流程逐步骤[端·应然·实测·判定·驱动·截图] / 右下问题+修复意见）。这是每轮测试的最终交付物。

**⑧ 闭环修复**：读问题清单 → 责任定位（前端漏按钮/后端 scope 错/迁移缺种子/前后端契约不一致）→ 改**产品代码** → 重跑该系统 → 该 finding 从红转绿。

## 两个端到端 worked example（参考平台实测）

### 例A · 正常流程怎么被逐步骤浏览器驱动（INFO 资讯三级审核）
- **应然（时序图）**：编辑撰写草稿 → 提交 → 二审(处室) → 三审(办公室) → 定时发布。状态链 `草稿→审核中→通过→已发布`。
- **抽泳道**：撰写/发布=管理后台(编辑)、二审=CITY 审核员、三审=PROV 审核员。
- **摸实现**：`PostManage.vue` 有「提交审核」「发布」行按钮（状态条件显隐）；`ReviewTodo.vue` 有「通过/驳回」，approve 带 `ElMessageBox.prompt`（意见可选）；审批 def6030 两节点。
- **写探针**：`op` 点「提交审核」→回查 `postStatus=审核中`；`cauPage` 审核待办点「通过」→`pauPage` 审核待办点「通过」→回查 `通过`；`op` 点「发布」→回查 `已发布`。每步 `uiDrive` + `api` 回查。
- **结果**：三步全 PASS（提交/两节点审核/发布都是浏览器点真按钮驱动、后端坐实）。

### 例B · 怎么测出真 bug 并闭环（STATION 审核待办）——体现「浏览器测试 > 接口测试」
- 探针要在【审核待办】页点「通过」办结站点备案审核时，发现**该页面是只读的、根本没有「通过/驳回」按钮**——审核员无法在页面办结（接口层面 `POST /review` 能通，所以接口测试永远发现不了）。
- 按「点不到就算红」判 MISMATCH，并记根因（对比其它系统审核待办都有按钮，本系统缺操作列）。
- **闭环修复**：改产品代码——前端 `ReviewTodo.vue` 补操作列(通过/驳回)、`api.ts` 加按 bizType 分派到 `/site-stations|/site-activities|/site-registrations` 的 review 函数。
- **重跑**：备案审核经新按钮 UI 两节点办结转绿。这条缺陷正是「逐步骤浏览器点真页面」才暴露出来的。

> 另一条同样有价值：SCIFIT 社指员在页面看不到该响应的公众咨询。**下结论前必读源码**——最初误判为"列表按 user_ref/region 过滤"，读源码才坐实真因是**公众建单时 instructor_ref 留空(待响应池)**，社指员 scope 匹配不上。改「让社指员可见未分派的待响应池」后转绿。教训：坐实再下结论（纪律②）。
